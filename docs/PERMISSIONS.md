# 角色与数据权限设计

数据权限由 FastAPI 对当前身份、动作和目标范围统一求值。来源包括业务库角色和部门授权、项目成员关系、资源所有者，以及请求入场归属快照。

| 资源或动作 | 普通用户 | 部门主管 | 超级管理员 |
| --- | --- | --- | --- |
| 调用记录、用量和费用 | 本人 | 本人及当前获授权部门的记录 | 全公司 |
| 成员名册、组织和项目资料 | 本人 Key 或记录中的可见归属标签 | 当前获授权部门，及关联项目的必要资料 | 全公司管理 |
| 跨部门项目统计 | 本人份额 | 各获授权部门份额 | 全项目 |
| 子 Key | 读本人掩码，获授权后领取本人明文一次 | 授权部门 Key 掩码及状态，兼有本人领取能力 | 授权发放、暂停、恢复、轮换和撤销；明文仍由所有者领取 |
| 配额 | 本人可见的 Key 限额及使用 | 获授权部门的 Key 数据及该部门费用份额 | 管理 Key 和项目额度 |
| 供应商、路由、价格、系统开关 | 仅可见记录所需字段 | 同普通用户 | 管理配置及凭据引用 |
| 告警 | 仅本人调用的风险状态 | 获授权部门的告警摘要 | 全公司确认及结案 |
| 管理审计和风险证据 | 无权限 | 无权限 | 管理审计可读。风险证据另需显式权限并记录访问。 |

## 授权执行

- 管理 API 首先验证签名、会话和凭据版本，再用当前角色与授权求值。普通用户按记录所有者过滤。部门主管读历史按请求快照部门，读名册按当前关系。授权移除后立即重新求值。
- 作用域先应用到 Repository 查询，分页总数、聚合、自动补全、下钻和导出复用同一个谓词。通过 ID 访问同样检查作用域。多个部门参与的项目以项目和部门组合分组，部门主管的汇总和告警不可揭示其他部门费用或全项目共享余额。
- 网关校验平台 Key、所有者状态、部门状态及当前归属、项目状态、项目部门和成员关系、模型和协议。请求中的 `user`、`project_id` 等字段不能替代服务端授权。FastAPI 向 LiteLLM 使用私网服务 Key，后者权限不用于门户数据授权。
- 管理员负责授权，只有 Key 所有人可领取明文；轮换共享原授权的模型范围和预算周期。离职、调岗、移除成员、停用部门、归档项目和撤销 Key 均阻止新的相关准入。已开始请求保留入场归属和结算能力。
- 受限证据访问独立审计。拒绝记录稳定原因，与真实标识、密钥、原文和内部策略细节分离。

## 验收用例

准备两个部门、一个共享项目、一个独立项目、两名主管及一名转岗用户。按 [API 契约](API.md) 验证正反向访问、列表与聚合口径、角色与授权撤销、Key 领取和暂停、跨部门告警隔离。各条测试证据见 [开发与验收计划](DEVELOPMENT_PLAN.md)。
