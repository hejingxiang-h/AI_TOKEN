# 项目需求规格说明书

AI Token Gateway 面向公司内部研发人员、部门主管和超级管理员。它将公司授权的模型供应商密钥集中保存在服务端，由开发者使用可撤销、可限额的子 API Key。平台依据已授权的项目关系记录用途归属，审计人员可结合调用与风险信息开展核查。

## 业务对象和规则

| 对象 | 规则 |
| --- | --- |
| 用户与部门 | MVP 每个用户具有一个有效主部门。部门主管单独授权一个或多个部门，授权范围按部门 ID 校验。停用用户或部门阻止相关子 Key 的新请求。 |
| 项目与成员 | 项目可允许多个部门参与，须同时具有项目成员资格和部门授权才能签发及使用子 Key。归档项目保留历史记录并拒绝新请求。 |
| 子 API Key | 归属固定为一个用户、一个部门、一个项目，配置模型白名单、有效期、暂停和撤销状态。管理员授权签发或轮换，Key 所有人登录后可领取一次明文，后续只展示非敏感标识。 |
| 调用归因 | 网关以子 Key 绑定及服务器权限为准。请求自带项目、部门和用户信息不参与计费归因。调用入场时写入归属快照，人员转岗触发原 Key 失效与重新签发。 |
| 使用目的 | 项目成员和 Key 归属反映授权范围。内容风险与用量模式可作为复核信号，由授权人员判断调用用途。 |
| 时间与币种 | 库内统一存 UTC，默认企业时区拟为 Asia/Shanghai。日期使用半开区间，统计按调用开始时间归属。跨币种分组显示，配额同币种计算。 |

## 功能需求

| 编号 | 需求与业务规则 |
| --- | --- |
| FR-01 | 提供管理员建立账号、本地登录、退出、密码重置和会话失效。停用账号后，后台访问和网关访问均须受控。 |
| FR-02 | 管理用户、部门、项目及项目成员、部门授权关系。以停用或归档保留历史。 |
| FR-03 | 提供三个内置角色和主管部门授权。每个业务接口在后台进行资源和范围校验。 |
| FR-04 | 支持子 Key 签发、一次性展示、有效期、允许模型、暂停、恢复、撤销、轮换和查询。轮换用新 Key 发起请求，旧 Key 自约定截止时间拒绝新请求。 |
| FR-05 | 配置项目和子 Key 月度费用额度、子 Key RPM 和并发上限，并提供越限原因及项目、部门、用户和 Key 紧急停用入口。 |
| FR-06 | 管理供应商、模型实例、路由别名、启停、凭据引用和生效价目。测试连接返回脱敏结果，在核验通过后启用。 |
| FR-07 | 暴露已验证的模型 API。执行认证、归因、模型授权、请求限制、配额预留、代理转发与结算，并提供可关联的请求 ID。 |
| FR-08 | 提供今日、昨日、最近 7 天、最近 30 天、本月、自定义范围的趋势、汇总与对比。默认今日。最近 N 天含今天，按 N 个日历日计算。自定义按企业时区选起止日期，拟限制单次 90 个日历日。未来日期禁选，跨越当前时刻的区间只统计到当前时刻。 |
| FR-09 | 展示调用记录和详情，支持按授权范围、模型、项目、Key、状态及风险筛选，展示用量来源与账务状态。 |
| FR-10 | 保存管理审计，涵盖登录安全事件、角色与授权、凭据元数据、配额、价目、风险处置和敏感审计访问。 |
| FR-11 | 提供风险告警与处置记录。首版使用配额阈值、拒绝突增、调用异常和疑似敏感内容规则，支持去重、确认和结案。 |
| FR-12 | 管理企业时区、脱敏与留存策略、全局网关开关、默认阈值。高影响操作记录操作者、原因和结果。 |

## 调用记录和统计口径

| 字段组 | 内容 |
| --- | --- |
| 归因 | 请求 ID、用户 ID、子 Key ID 和掩码、部门与项目快照、供应商、模型别名、实际模型标识、协议、供应商请求 ID（若返回）。 |
| 时间与状态 | 开始、结束、总耗时、可选首字节耗时、是否流式、HTTP 状态、业务状态、拒绝/失败/断流/取消原因及上游是否已发起。 |
| 用量 | 输入、输出、总 Token、缓存读取、缓存写入、可得时区分缓存写入时长及推理 Token。记录来源、归一化规则版本和待确认状态，缺失字段用空值表示。 |
| 费用 | 每个计价项、价目版本、原币、金额、结算状态、调整记录。分别展示已确认金额、预留金额及待核对笔数。 |
| 风险 | 风险标志、规则版本、等级、告警 ID、处置状态。限制敏感证据字段的访问。 |

调用量包含网关记录的成功、失败和拒绝。无法解析归属的认证失败记入安全审计。Token 与费用汇总以确认账目为准，附带待核对计数。账务调整回写原调用时间维度并记录调整时间。部门和项目对比使用明细相同的权限、日期和币种筛选。日内按小时、跨日按日聚合，区间均到查询时刻或所选末日边界。

## 告警和审计规则

- 配额按项目与子 Key 分别判断。试点拟在当月用量或有效预留首次触及 80% 时告警，达到上限或因剩余不足而拒绝时记录越限原因。重复命中合并并更新次数和最近时间。
- 调用异常优先覆盖持续上游失败、同一归属的拒绝突增、未结算请求积压和疑似敏感内容。阈值、规则版本和观察窗口写入告警，确认人、结案人和处置原因可追溯。
- 内容审计在请求发送前和流式响应途中做限量检测，首版拟检测明显凭据格式与企业批准的敏感标识。仅在需要复核时保存脱敏片段，流式响应侧的告警可在部分内容已交付后产生。风险分为未命中、命中和无法判定，截断或扫描失败须可识别。

## 非功能需求

- 权限和密钥。所有查询、聚合、详情、配置写入及告警处置均要求服务端鉴权。全链路使用 TLS 或受控私网，凭据和授权头从持久日志、错误和前端遥测中移除。
- 审计和隐私。首版记录元数据、规则命中情况及受限的脱敏片段。完整内容长期留存、保留期限、适用数据类别和跨境通道需由企业负责人批准后另行启用。建议试点元数据 90 天、审计记录 180 天、脱敏风险摘要 30 天，正式值待确认。
- 可用性和准确性。请求账务具备去重、恢复和差异追踪能力。配额失去可信状态时关闭受影响的新调用，保留故障与恢复证据。备份恢复及性能门槛见验收方案。
- 使用环境。PC 浏览器内网使用，试点覆盖受管 Windows 上的 Edge 或 Chrome，支持按权限显示入口与可访问的表格、表单及错误反馈。
- MVP 边界。覆盖已配置网关地址的受管调用。直连供应商、个人订阅、客户端非模型服务、代理无法看到的本地工具执行过程均在覆盖范围之外。业务归属和风险结果提供审计线索，内容始终有盲区。
