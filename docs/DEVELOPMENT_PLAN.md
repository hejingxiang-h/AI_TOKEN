# 开发阶段与验收计划

阶段四交付前后端基础工程、独立部署配置和基础运行证据。业务模块在阶段四验收后单独确认。已有范围见 [需求与技术评审](README.md)。

## 技术决策

| 决策 | 理由和复核条件 |
| --- | --- |
| FastAPI 模块化单体加私网 LiteLLM Proxy | 保持控制面与推理准入的业务规则统一。用固定版本 Proxy 提供上游协议和认证。 |
| 业务 Key 与 LiteLLM 服务 Key 分离 | 保持项目、部门、身份权限的唯一权威来源。轮换沿用原 Key 授权范围和额度。 |
| PostgreSQL 双范围原子预留与结算 | 避免并发时跨项目和 Key 额度失真。Redis 承担 RPM 和租约，不承担已消费金额。 |
| 响应中的用量为主要证据，代理回调支持补偿 | 支持同步和异步证据交叉核对。回调需签名、去重和持久入库。未知用量保持待核对。 |
| OSS 优先验证，商业许可按需评估 | 首版平台权限、记账与审计均有自有接口。商业能力用于后续采购评估。 |
| Responses 先实测兼容再安排发布 | P0 覆盖三条首发路由。Responses 与 Codex 在独立接入验收后开放。 |

## 阶段交付与门槛

| 阶段 | 验收产物与门槛 |
| --- | --- |
| 详细设计与 PoC | 架构边界、数据库 ER、API、权限、安全和验证材料。明确区分官方证据、模拟结果和真实供应商验证。 |
| 阶段四 工程初始化 | 验收 Python 与 npm 依赖、FastAPI、Swagger、真实依赖探活、Alembic 生成和执行、Vue 路由与 Axios、前端生产构建。Docker 检查 Compose 配置。保留独立 PoC。 |
| 基础业务实现 | SQLAlchemy 模型和 Alembic 迁移，组织、项目、角色以及 Key 收领和生命周期。Pytest 权限测试及 Playwright 管理操作验收。 |
| 网关与账务实现 | 三条首发路由、协议级 usage、预算和限流、结算及恢复。检查 Redis 故障、并发、月度边界、重复事件和账本一致性。 |
| 内部试点 | 真实供应商流式和工具验证，财务核对、安全日志、灾备、负载和脱敏。上线前完成全部 P0 门槛。 |

## 阶段四边界

- 管理后台提供系统健康页。应用入口分别处理存活和就绪请求。就绪检查并发验证 PostgreSQL 和 Redis。
- 基础迁移仅初始化 Alembic 版本记录。功能表及不可逆数据库变更另行评审。测试迁移在隔离数据库和临时迁移目录执行。
- 新 Compose 使用独立项目名、数据卷、业务及代理库。模型管理接口只在私网开放。Nginx 留出 SSE 路由，推理准入在进入后续阶段后开发。
- 阶段四不启动全套容器。部署联调、真实上游和 LiteLLM Virtual Key 生命周期、白名单、Budget、RPM 仍按各自验收执行。

## 未解决问题与证据

| 问题 | 验证方法 |
| --- | --- |
| Docker 和目标环境实测 | 在可用 Linux Docker 环境运行 [PoC](poc/litellm/README.md)，记录 Proxy 镜像摘要和 PostgreSQL 版本，先复测 Virtual Key、禁用和撤销、模型白名单、预算及 RPM，再复核 Redis 多实例及故障策略。 |
| 真实供应商、地区和模型 | 使用企业授权凭据逐条调用，关联账单及脱敏用量证据，验证缓存、工具、限流和失败行为。 |
| 内部事件标识传播 | 每种入口在流式、非流式和错误状态验证平台 ID、代理 ID 及供应商 ID；验证重启后的补偿查询。 |
| 生产 callback 完整性 | 运行签名、拒签、重放、重试、重复异文、乱序和宕机恢复测试。以业务库唯一约束和账本不重复为准。 |
| 缓存写入和预算上界 | 按模型和计价版本验证最坏输入与输出，并压测同范围并发。超预留、挂起费用、停用及跨周期调整均保留证据。 |
| 待确认运营参数 | 试点模型、费用上限、部门和项目范围、保留策略、内部回调密钥轮换及风险阈值由负责人确认。 |

PoC 的实际命令和逐项结果见 [运行记录](poc/litellm/RESULTS.md)，真实验收口径见 [验收基线](06-delivery.md)。业务开发状态由 [进度记录](PROGRESS.md) 更新。
