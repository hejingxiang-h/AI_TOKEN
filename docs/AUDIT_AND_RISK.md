# 阶段九审计与风险告警

调用记录继续使用真实网关账本。详情显示调用人、部门、项目、Key 标识、模型、时间、Token 用量、费用、状态和终止时间。新增来源 IP、客户端类别和风险状态。管理员可以在详情查看来源 IP，普通用户和主管的详情会将该字段隐去。客户端类别按 User-Agent 允许列表归类，属于诊断线索。未识别的类别显示未知，完整 User-Agent 不落库。用量汇总仍使用相同的权限条件。

## 管理与告警接口

- `GET /api/v1/audit-events` 服务端仅允许超级管理员访问。记录操作者、时间、目标、动作、结果及允许列表内的变更摘要。摘要只存字段名称和受限状态、角色等枚举，禁止传入密码、密钥、显示名、原始请求正文。已认证的失败写操作记录路由模板和状态码。
- `GET /api/v1/alerts` 分页，支持状态过滤。普通用户查看本人告警，部门主管还可看授权部门告警。跨部门聚合及来源 IP、供应商、网关类告警由管理员查看。项目级阈值含全项目费用，当前由管理员查看。
- `PATCH /api/v1/alerts/{id}` 由超级管理员执行确认与解决，记录审计。重复相同操作返回当前状态。待处理告警可确认或直接解决，已解决为终态。重复扫描更新同周期的观测结果，不重置处理状态。

## 告警口径

额度与网关准入使用相同 UTC 日及月口径。达到额度的 80%、90%、100% 创建对应事件。同一额度规则、周期和阈值最多保留一条。账本保留历史，周期由时间边界自然滚动。当前余额按已结算金额、在途及待核对预留计算。

异常检测包括短时高频、高额消费、无效或停用 Key 高频、供应商连续错误、网关异常、用量写入或结算异常、以及已入库的账单差异。异常事件使用目标和观察时段去重，单请求结算问题使用请求及问题类型去重。告警记录仅展示计量证据。供应商账单导入仍由后续对账流程提供，现有 worker 核对账本上已录入的可比较金额。

## 独立任务进程

应用迁移 `0008_risk` 后启动 Compose 的 `worker` 服务。本地可运行 `uv run python -m app.tasks.risk_worker --once` 验证单轮，去掉 `--once` 连续运行。每轮使用 PostgreSQL advisory lock 防止多个 worker 同时扫描，Web 进程保持请求内的结算，周期扫描、Redis 结算日志补偿及过期预留标记由 worker 负责。阈值由 `APP_RISK_INTERVAL`、`APP_RISK_FREQUENCY`、`APP_RISK_HIGH_COST_USD`、`APP_RISK_PROVIDER_ERRORS` 和 `APP_RISK_INVALID_KEYS` 配置。数据库不可写时，采集故障通过运行日志暴露，部署应由外部监控接收。

来源 IP 由 ASGI 客户端地址取得。Nginx 清洗客户端转发头。部署方需通过 `APP_TRUSTED_FORWARDERS` 仅信任实际代理地址或专用网段，后端不可直通用户网络。未启用可信代理时，记录的是连接对端。

## 内容审计

首版收集元数据，并通过独立告警类型与证据 Schema 预留扩展。Prompt、代码和模型回答全文默认不收集。开启内容采集前须评审企业政策，完成员工告知，明确最小权限、脱敏、保留期限和删除流程。风险信号用于核查，不直接定性员工违规。
