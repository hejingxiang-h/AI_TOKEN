# 技术风险与交付验收

以下为首版评审和进入开发后的验证计划。量化门槛、试点规模和通过条件是建议值，须在开发前由负责人确认。真实验证使用专门的测试账户、隔离路由和受控费用额度。

## 技术风险与验证计划

| 编号 | 风险或待验证事项 | 验证方法与通过证据 | 建议负责人与门槛 |
| --- | --- | --- | --- |
| R01 | 三家供应商授权、可达性、模型与数据政策 | 用企业试点账户从目标网段进行直连及代理调用。记录账户权限、模型 ID、TLS、延迟、上游数据策略及允许的数据类型。验证上游密钥与个人订阅隔离。 | 基础设施、信息安全。P0 阻塞。 |
| R02 | 流式、工具、缓存与终止用量可能在代理中改变 | 对每条路由比对直连和代理的脱敏协议样本。覆盖工具回传、SSE 正常结束、中断、服务失败、缓存读写和推理用量（适用时）。缺完整用量须留待核对证据。 | 网关、测试。P0 阻塞。 |
| R03 | 预算预留上界、并发竞态和停用传播 | 多实例并发请求同一 Key 和项目，覆盖同时调整额度、缓存故障、时间边界和撤销。比对准入、预留、账本和上游次数。用边界请求检查 token 上界及高价计价项。 | 后端、测试。P0 阻塞。 |
| R04 | LiteLLM OSS 版本、协议权限及功能许可漂移 | 固定候选版本和 digest，以无许可证实例验三条路由、虚拟 Key、白名单、日志脱敏和关联字段。检查发布说明、许可证、镜像配置及依赖；升级前同样回归。 | 架构、运维。P0 阻塞。 |
| R05 | 掉线、崩溃或重试导致漏记、重复计费或预留滞留 | 在准入、发送边界、流末、结算前后和后台入账阶段注入故障。核对一次性结算、定期恢复、陈旧预留可见性，以及上游账单和请求 ID 是否可关联。 | 后端、网关。P0 阻塞。 |
| R06 | 跨部门项目、转岗或权限变更造成横向泄漏 | 构造两个部门共同项目、一个仅本部门项目、至少两名主管及一名转岗员工。覆盖列表、分页总数、看板、按 ID 取详情、筛选项、告警和会话失效。 | 后端、测试。P0 阻塞。 |
| R07 | 供应商计价粒度、价目漂移或账单差异 | 建立按模型、价目版本、币种和请求类型的价格样本。使用 Decimal 独立复算单位换算、缓存折扣及写入倍率。核对供应商可得的使用或账单数据，记录折扣、税与无法归属的差异。 | 财务、后端。P0 阻塞。 |
| R08 | 凭据和敏感内容经错误、日志、回调或告警外泄 | 用无真实秘密的标记串覆盖请求、响应、异常和断流。检查应用、Nginx、LiteLLM、回调、数据库、告警与前端遥测。验证证据访问授权与留存清理。 | 信息安全、运维。P0 阻塞。 |
| R09 | 客户端协议及套餐变化 | 按接入矩阵对 Codex、WorkBuddy、Qoder 验证版本、套餐、实际请求路径、工具、SSE、额外服务和撤销。Claude Code P0 完成有限冒烟。客户端与已验收 SDK 分别出具通过证据。 | 客户端、测试。通用 SDK 为 P0，重点客户端按阶段。 |
| R10 | 服务容量、Redis 丢失和单节点恢复 | 在试点规格上执行并发、滚动重启、数据库备份还原和 Redis 故障演练。验证回滚、限流降级、账本恢复、备份有效性和业务告警。 | 运维、测试。P0 阻塞。 |
| R11 | 审计或风险规则被误解为用途证明 | 用批准的合成用例评估缺失、误报及管理员操作，校验摘要脱敏和内容政策。评审项目声明、授权和用途复核职责。 | 产品、信息安全。P0 验收。 |
| R12 | 可见范围与管控边界被绕过 | 梳理受管终端、代理出口和已有个人凭据。通过授权网络观察记录哪些模型请求走平台，哪些属于客户端自有服务，并确认企业是否采用额外终端和出口管控。 | IT、信息安全。试点准入。 |

开项待确认内容包括试点公司部门和人员、供应商账号与测试预算、模型和企业区域、脱敏与留存策略、财务对账联系人、部署规格、时间区间及币种。版本和 SLA 门槛随试点条件确认。

## 开发阶段及验收标准

| 阶段 | 交付成果 | 阶段通过条件 |
| --- | --- | --- |
| 0 需求与调研 | 需求、产品、架构、接入、许可及验收文件 | 业务负责人确认范围、权限、默认策略和 P0 上线边界后进入 PoC。 |
| 1 技术 PoC | 固定镜像的协议与账务证据，供应商接入、公司网络和密钥隔离结论 | 三条真实路由验证 JSON、SSE、基础工具、用量与价目。签字确认阻塞项 R01–R05、R07 的解决路径，记录所有允许上线的模型和参数。 |
| 2 基础管理与鉴权 | 用户、部门、项目、角色、会话、Key、供应商及模型配置 | 通过权限及密钥验收。完成初始化、权限撤销与紧急停用流程。 |
| 3 网关、账务及运营面板 | 请求代理、配额、结算、看板、调用、审计及告警 | 业务主路径、协议用量、故障恢复、时间维度及对账验收全部通过。 |
| 4 内部试点与上线 | Compose 运行、企业终端验收、安全扫描与应急响应方案、监控及恢复演练 | 业务、财务、信息安全和运维确认验收证据，零未关闭 P0 缺陷。先小范围上线，经复核再扩大。 |
| 5 版本扩展 | 按发布单新增供应商、模型协议或客户端 | 逐组合验收，版本升级和回滚复用原三路由回归包。 |

## 量化验收用例

| 验收项 | 建议通过条件 | 证据 |
| --- | --- | --- |
| 真实调用和协议 | 三条首发路由各覆盖至少 12 次受控真实调用。每条含非流式、SSE、基础工具及回传、正常结束和上游错误；断流和缓存场景按供应商能力验证。 | 标准 SDK 测试记录、脱敏事件、模型与镜像清单。 |
| 用量准确性 | 有完整供应商用量的样本，输入、输出、缓存和总量与归一化规则比对逐笔一致。缺失用量样本全部进入待核对，确认账目无默记零。 | 供应商 JSON/SSE 样本、用量归一化对照表。 |
| 费用可靠性 | 预先设定的单价与用量样本全部和独立 Decimal 复算一致。试点账单可归因差异逐笔或按凭据与时间窗口解释。 | 固定价目版本、样本清单、差异报告与财务确认。 |
| 权限隔离 | 三角色的正向和反向矩阵全通过。跨部门项目的汇总、详情、告警及筛选项无越权泄漏。角色和归属变更的访问行为与规格一致。 | Pytest API/数据库集成、Playwright 关键路径。 |
| 配额和撤销 | 至少两业务工作进程、32 个竞争请求下预算不超已验证准入上界，超限给出明确理由。撤销提交后 2 秒内探测请求全部拒绝，已入场记录按状态落账。 | 并发压测、上游调用数、事务记录和时间线。 |
| 账务恢复 | 代理和业务进程重启、Redis 不可用、消息重放和断流测试均能定位请求。重复结算数为 0，未决记录有恢复或人工处理入口。 | 故障演练、任务记录和账本检查。 |
| 报表和审计 | 默认今日，并覆盖指定的全部时间范围、午夜和月末、空数据与币种分组。看板和明细的金额、调用次数、Token 按同口径核对。敏感证据和凭据变更访问均有审计。 | 准备的基准数据、界面回归和审计记录。 |
| 安全与告警 | 明文凭据在日志、业务数据库、前端遥测和其他非授权存储中的匹配数为 0。经批准的密钥存储按访问控制单独验收。模拟配额阈值、异常调用及风险摘要可触发合并告警，可暂停、确认、结案，并留下原因。 | 哨兵值检索、Playwright、审计和告警记录。 |
| 基本性能与恢复 | 固定试点规格下，32 个在途请求时平台附加准入及代理转发耗时 P95 ≤ 200 ms，以上游替身做基线并排除上游生成时间；独立恢复演练目标 RPO ≤ 24 小时、RTO ≤ 4 小时。 | 压测配置、统计样本、备份和恢复时间线。 |

上线材料包括版本和镜像清单、功能与权限回归结果、三条路由证据、财务核对说明、终端配置说明、部署与回滚手册、安全审计和待解决事项清单。任何需要进入下一阶段的实现或真实测试，由需求评审确认后开展。
